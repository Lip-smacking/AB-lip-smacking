# ICIO 动态模块参考

仅在用户需要完整教学、复杂诊断或框架对比时读取。普通提示词优化优先使用 `SKILL.md` 的快速模式。

## 四种框架

### 1. 人格魅力型（Charisma）

适合商业咨询、创意写作、角色扮演、风格模仿和文案等高度依赖表达人格的任务。

推荐模块：角色（Role）、语气（Tone）、风格（Style）、示例（Example）、意图（Purpose）。

选择原则：结果好坏主要取决于“像谁说、以什么气质说、写成什么感觉”，而不是严密流程。

### 2. 逻辑执行型（Execution）

适合技术任务、自动化、代码、报告和可重复交付等需要稳定执行的任务。

推荐模块：角色（Role）、任务（Task）、工作流程（Workflow）、要求（Request）、约束（Constraint）、格式（Format）。

选择原则：结果必须可预测、可检查、可重复，遗漏步骤或格式会导致实际失败。

### 3. 战略分析型（Strategy）

适合市场分析、商业策划、竞品研究和决策支持等需要判断与备选方案的任务。

推荐模块：角色（Role）、目的（Objective）、背景（Background）、挑战（Challenge）、问题（Problem）、方案（Solution）。

选择原则：用户真正需要的是洞察、权衡和决策依据，而不是单一执行结果。

### 4. 全能大师型（Omni-Master）

适合游戏设计文档、完整商业计划等同时需要创意、逻辑和战略的高复杂度任务。

从全部模块中按需组合，但不要默认全选。只有模块缺失会实质降低结果时才加入。

## 常用模块定义

- **目标（Goal）**：最终要获得的具体交付物或终点状态。
- **目的（Objective / Purpose）**：为什么要获得它，以及它要带来的价值。
- **角色（Role）**：完成任务所需的专业视角；只有角色会改变判断方式时才设置。
- **任务（Task）**：AI 要完成的单一核心动作。
- **背景（Background）**：理解任务必需的事实、受众和使用环境。
- **挑战（Challenge）**：阻碍成功的主要难点或冲突。
- **问题（Problem）**：需要被分析或解决的明确问题。
- **方案（Solution）**：期望生成的建议、路径或备选方案。
- **要求（Request）**：结果必须满足的正面条件。
- **约束（Constraint）**：不能发生或不能超出的边界。
- **流程（Workflow）**：任务确实依赖顺序时才规定的步骤。
- **格式（Format）**：输出结构、长度、字段或文件类型。
- **语气（Tone）**：表达的情绪和交流姿态。
- **风格（Style）**：语言、视觉或专业呈现方式。
- **示例（Example）**：用于校准质量与形式的少量代表性样本。

## 诊断问题库

按需选择，不要逐题盘问：

- 最终要得到什么具体成果？
- 这个成果将给谁使用，在哪里使用？
- 已有哪些输入材料或可信事实？
- 怎样判断结果是成功的？
- 哪些内容必须出现，哪些绝对不能出现？
- 输出需要什么结构、长度或文件格式？
- 是否有一个可代表期望效果的示例？

## 快速判断示例

| 用户需求 | 推荐框架 | 关键原因 |
|---|---|---|
| 写一封具有创始人口吻的品牌信 | 人格魅力型 | 人格与表达风格决定质量 |
| 生成可运行的数据清洗脚本 | 逻辑执行型 | 流程、约束与验收标准关键 |
| 比较三个市场进入方案 | 战略分析型 | 需要多维权衡与决策建议 |
| 编写完整商业计划书 | 全能大师型 | 创意、逻辑和战略同时存在 |

## 共建模式建议

1. **战略定位**：确认目标和目的。
2. **执行构建**：确认任务、必要角色、背景、要求与约束。
3. **交付标准**：确认格式、风格与成功标准。
4. **整合交付**：输出一份自包含提示词，并简短说明为何选择该框架。

如果用户在任一阶段已经给出答案，直接复用，不要求重复填写。
